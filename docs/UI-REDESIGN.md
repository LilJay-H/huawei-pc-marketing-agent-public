# 前端工作台改版说明

本次保留「校园有解」的大学生场景、真实资料检索和核验流程，将前端调整为华为红与浅色背景的双栏内容工作台。运行仍只需要 Python 标准库，前端无框架、无运行依赖、无需构建。

## 结构与设计

- `web/index.html`：语义化页面、创作配置、空态、加载态和结果容器。
- `web/styles.css`：统一的品牌色、语义色、间距、卡片、表单及响应式规则；900px 以下单栏，支持减少动态效果。
- `web/app.js`：配置加载、请求与取消等待、结果渲染、Markdown 安全呈现、复制及导出。
- `server.py`：仅增加 `/styles.css` 与 `/app.js` 静态白名单，不开放任意目录，也不改变业务接口。

配置按产品、校园场景、平台分组；版本、人群目标、细分任务可按需展开。场景与平台用原生 radio 实现单选，支持键盘方向键；错误反馈、配置重试、请求取消、来源徽章和核验状态均有文字说明。

结果按照场景、依据、图文、核验四段组织。正文渲染标题、列表、加粗、引用等常用 Markdown，原始文本保持不变，复制与导出不会混入内部策略。原文与追踪采用折叠展示；有风险的草稿明确标识，保留逐项修改建议、未检查范围及待确认事项。

## 与参考提示词的适配

参考稿用于视觉与交互方向，接口以当前仓库实现为准：

| 功能 | 当前真实接口 |
| --- | --- |
| 场景、平台、配置状态 | `GET /api/config` |
| 本地型号建议 | `GET /api/products` |
| 连接测试 | `POST /api/connect` |
| 仅检索资料 | `POST /api/retrieve` |
| 生成图文 | `POST /api/generate` |
| 证据快照改写 | `POST /api/rewrite` |

不引入不存在的 `/api/meta`，不硬编码产品列表或生成内容，不添加没有后端支持的违规/事实注入开关。来源徽章根据本次结果的 `source_kind` 显示，快照改写单独标注；未取得资料前显示待确认。修改型号、版本或来源后，必须重新检索生成。

所有服务文本通过 DOM `textContent` 写入。Markdown 不执行 HTML，也不加载文中图片或链接。配图仅接受 HTTPS 或同源的本地图片接口。核验记录延续原有字段白名单，不导出签名图片 URL。

## 验证与复现

启动：

```sh
python server.py
```

打开 `http://127.0.0.1:8765/`。后端回归测试：

```sh
python -m unittest discover -s tests -v
node --check web/app.js
```

可选浏览器验收使用 Playwright 和 Edge，仅用于开发测试，不是应用运行依赖。在能解析到 Playwright 的 Node 环境执行：

```sh
node tests/test_frontend.cjs
```

截图和报告保存到已忽略的 `.runtime/ui-checks/`。浏览器套件验证真实本地配置、型号、资料与图片；生成草稿、风险、故障、改写等分支使用明确标注的合成测试夹具，不能作为模型生成质量的证据。若当前未配置文案模型，还会验证真实生成接口返回待配置状态且不交付伪造正文。

初次界面验收环境：Windows / Edge；375、768、1024、1440px，以及 667×375 横屏；减少动态效果、键盘单选、复制导出、异常重试、取消等待、缺资料追问、改写限制、配置失败和文本注入防护。当时后端 43 项测试通过，尚未配置模型；后续真实生成结果见下文。

## 生成输出问题复核（2026-10-18）

本地用户点击生成后的实际状态是 `model_required`，不是仍在执行。该次请求成功读取 HUAWEI MateBook 14 的 5 份产品资料、19 张图片，但因缺少模型配置，没有执行事实提取、写作或审稿。

本轮修正：

- 模型未配置时，在配置按钮旁和工作区顶部明确说明目前只能检索资料；按钮改为「检索资料（模型待配置）」。返回结果标出「已结束 · 正文未生成」、资料/图片数量、核验未执行。
- 提供缺失配置项名称与本地配置步骤、重新检查配置按钮；不读取或显示密钥值。刷新配置保留当前型号、场景、平台等输入。
- 本地目录的 MateBook 14 名称省略了鸿蒙后缀，而图片索引带「鸿蒙版」，原代码错误地判定 19 张图片均不符。增加由本地资料适配器提供的目录型号与分类，仅在明确属于 `01-鸿蒙电脑` 且目录型号与请求一致时认可这一别名。Windows、无目录身份、其他型号或 ima 结果不套用此规则；年份和版本仍单独核对。快照改写和核验导出保留该目录身份。
- 新增 HTTP 全链路契约测试，覆盖小红书、公众号、朋友圈、海报。使用合成证据与模型响应替身，实际执行本地检索、模型适配器、事实提取、审核、来源哈希、会话保存和结果返回；不代表真实模型生成质量。

此阶段 47 项后端测试、15 组浏览器检查通过，随后用户填写了本机模型配置并进行了以下真实验收。密钥配置文件被 Git 忽略，不随推送上传。

补充复核：19 张 MateBook 14 图片中，4 张官网图有型号字段，别名修正后可通过索引核验；其余 15 张商城图的 CSV 本身没有产品型号字段，应为「待核验」，而非「型号不符」，也不能直接放行。已修正这一分类，并在写作前提供图片索引核验结果，让模型优先选用已有匹配依据的图片。真实图片像素、具体配置和授权仍需人工确认。

## 真实模型验收（2026-10-18）

使用本地 v7 产品资料和用户配置的 DeepSeek 服务，通过真实 HTTP 生成接口验收；公众号同时在本机浏览器完成点击生成、正文展示、Markdown 与核验记录导出。没有使用固定正文或模型替身。

最初实测暴露出两类失败：事实提取把概括写进逐字引文，审稿响应把字符串数组写成对象数组。现在明确响应类型，并各允许一次格式或引文纠正；纠正后仍执行原有严格检查，连续失败仍停止交付。图片候选中已有足够索引匹配的资源时，仅将这些候选提供给写作模型，完整资源列表仍保留在证据结果中。

| 平台 | 实测输出 | 最终状态 |
| --- | --- | --- |
| 小红书 | 20.1 秒，正文 640 字符（含 Markdown），1 张配图 | `needs_review`：低于平台配图数量要求；一处接口功能表述的引用未覆盖全部断言 |
| 公众号 | 正文 855 字符（含 Markdown），2 张配图，4 项原文引文匹配 | `checked_draft`：本次自动检查无待修问题；浏览器显示、复制导出路径可用 |

上述实测证明可产出真实营销草稿，不代表每次生成均满足平台要求，也不代表已获发布批准。动态参数、SKU、软件兼容和图片授权仍按页面提示人工确认。本轮没有配置或实测实时 ima。

最终回归：51 项后端测试通过；模型已配置环境下 14 组浏览器检查通过。此前未配置环境的第 15 组真实 `model_required` 分支亦已通过。浏览器自动测试中的生成响应替身与上表真实调用分开记录。
